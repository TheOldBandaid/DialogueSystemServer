# Серверная часть системы управления диалогами игровых персонажей

Приложение на C#, ASP.NET Core 10 и SQLite: редактор графа, персонажи, условия переходов, прохождение с историей и сохранённые версии диалогов.

## Запуск в Docker

Нужен Docker Desktop в режиме Linux-контейнеров. Команды выполняются из корня проекта.

1. Скопировать `.env.example` в `.env`.
2. Задать в `.env` пароли `DIALOGUE_ADMIN_PASSWORD` и `DIALOGUE_EDITOR_PASSWORD` длиной от 12 до 512 символов. Файл `.env` исключён из Git и образа. Для паролей с `$` или пробелами использовать одинарные кавычки.
3. Собрать и запустить приложение:

```powershell
docker compose up --build -d
```

Открыть [http://127.0.0.1:5189](http://127.0.0.1:5189). Войти как `editor` для редактирования или как `admin` для управления пользователями. Порт можно изменить переменной `DIALOGUE_PORT` в `.env`.

Compose настроен для локальной демонстрации в Development и публикует порт только на 127.0.0.1. Контейнер работает от пользователя `app`. SDK .NET на компьютере для этого способа запуска не требуется.

База, ключи защиты cookie и резервные копии находятся в постоянном томе `dialogue-data`, внутри контейнера — в `/data`. Пересоздание контейнера сохраняет данные. Пароли из `.env` создают только отсутствующие начальные аккаунты; изменение `.env` не меняет пароль уже существующего пользователя.

Остановка и последующий запуск:

```powershell
docker compose down
docker compose up -d
```

Посмотреть журнал:

```powershell
docker compose logs --tail 100 server
```

## Резервные копии в Docker

Перед обслуживанием остановить сервер: один каталог данных одновременно использует один процесс.

```powershell
docker compose stop server
docker compose run --rm server --maintenance=backup
docker compose up -d
```

Команда выводит полный путь проверенной копии внутри `/data/backups`. Скопировать каталог копий на компьютер:

```powershell
docker compose cp server:/data/backups ./artifacts/docker-backups
```

Восстановление выбранной копии из постоянного тома:

```powershell
docker compose stop server
docker compose run --rm server --maintenance=restore --file=/data/backups/имя-файла.db
docker compose up -d
```

При восстановлении текущие файлы предварительно сохраняются, копия проверяется и при необходимости обновляется миграциями. Все прежние сеансы завершаются. Пользователи и пароли возвращаются к состоянию копии, после запуска нужно войти заново.

## Локальный запуск через PowerShell

Нужен .NET 10 SDK:

```powershell
.\Start-Demo.ps1
```

Скрипт запросит пароли отсутствующих начальных аккаунтов и запустит сервер на том же локальном адресе. Данные этого способа запуска находятся в `artifacts/demo-data`, отдельно от Docker-тома. Для другого каталога использовать `-DataDirectory`, для другого порта — `-Port`.

Для локального обслуживания при остановленном сервере:

```powershell
.\Maintain-Server.ps1 -Action Backup
.\Maintain-Server.ps1 -Action Restore -File 'полный-путь-к-копии.db'
.\Maintain-Server.ps1 -Action ResetAdminPassword -Login admin
```

В Docker восстановить забытый пароль администратора можно той же командой приложения:

```powershell
docker compose stop server
docker compose run --rm server --maintenance=reset-admin --login=admin
docker compose up -d
```

Команда запрашивает новый пароль и повтор. Прежние сеансы выбранного пользователя завершаются. В интерфейсе администратор также может выдать другому пользователю временный пароль с обязательной сменой при входе.

## Работа с диалогами

- В каталоге создать диалог или импортировать JSON. В редакторе добавлять реплики, выбирать персонажей и соединять реплики вариантами ответа.
- Назначить старт, отметить концовки и сюжетные развилки. Для сохранения решения игрока использовать состояния сюжета у переходов.
- Открыть карту или проверить диалог. Перед прохождением исправить ошибки, найденные проверкой.
- В предпросмотре выбирать ответы; пройденные шаги сохраняются в истории.
- В разделе версий сохранять снимки диалога, скачивать их JSON или открывать отдельной копией. Импорт поддерживает форматы JSON версий 1 и 2.
- Управление персонажами позволяет переименовывать говорящих, смотреть использования и переносить реплики. Для копии диалога или версии можно создать независимых персонажей.

Сохранения и удаления проверяют версии данных: устаревшая вкладка получает отказ вместо перезаписи чужой правки. Несохранённые изменения защищены подтверждением при переходах.

При удалении отдельной реплики история прохождения сохраняется. Удаление диалога удаляет связанные реплики, переходы, версии и историю после подтверждения.

## Хранение данных

Миграции выполняются автоматически при запуске. Перед обновлением существующей схемы создаётся проверенная копия. При ошибке копирования обновление не начинается.

Сервер создаёт ежедневные копии; хранятся семь последних ежедневных и три копии перед миграциями. Ручные копии и файлы перед восстановлением сохраняются. Экспорт одного диалога содержит только его данные, резервная копия БД включает также аккаунты, версии и историю.

Ключи cookie находятся в подкаталоге `keys` каталога данных. В Production требуется HTTPS; HTTP перенаправляется на HTTPS, cookie получает Secure, а внутренние подробности ошибок скрываются.
